# rzd-ticket-bot

Следит за свободными нижними местами на конкретный поезд РЖД и пишет в Telegram.
Работает в GitHub Actions — компьютер может быть выключен.

## Как работает

- По расписанию GitHub Actions запускает `check_rzd.py`.
- Скрипт делает тот же запрос, что и сайт ticket.rzd.ru (`Search/TrainPricing`), находит нужный поезд
  на каждую дату и суммирует по нужным типам вагонов нижние, боковые нижние, верхние места.
- Уведомление приходит, когда нижних мест стало больше, чем при прошлой проверке (в том числе 0 → 1),
  и когда они снова закончились. При первом запуске — сводка «взял на контроль».
- Состояние хранится в кэше Actions, а не в коммитах. После 6 ошибок подряд приходит одно предупреждение.
- Сертификат ticket.rzd.ru выдан Russian Trusted Root CA (НУЦ Минцифры), его нет в стандартных
  хранилищах; бандл лежит в `certs/russian_trusted_ca.pem` (Root до 2032, Sub CA до 06.03.2027).

## Настройки

Локально — `config.json` (в `.gitignore`), на GitHub — переменные репозитория, их заполняет `deploy.sh`:

| Переменная | Что | Пример |
|---|---|---|
| `ORIGIN_CODE` / `DESTINATION_CODE` | коды станций РЖД (express) | `2100001` Минск-Пассажирский, `2000006` Москва Белорусская |
| `ORIGIN_NODE` / `DESTINATION_NODE` | id станций для ссылки на поиск | `5a8ac9d9340c74258ad36784` |
| `TRAIN` | номер поезда, сравнивается по цифрам | `030` |
| `DATES` | даты отправления со станции посадки, через запятую | `2026-10-17,2026-10-24` |
| `CAR_TYPES` | `ReservedSeat` плацкарт, `Compartment` купе, `Luxury` СВ | `ReservedSeat` |
| `INCLUDE_SIDE_LOWER` | считать ли боковые нижние | `true` |
| `MIN_LOWER` | сколько нижних нужно для уведомления | `1` |

Поменять даты: `./bin/gh variable set DATES --body "2026-10-17"`.
Коды станций: `https://ticket.rzd.ru/api/v1/suggests?Query=Минск&TransportType=rail&GroupResults=true` (поля `expressCode`, `nodeId`).

**Дата — это дата отправления.** Поезд в 00:35 «17-го» уходит в ночь с 16 на 17.

## Команды

```
python3 check_rzd.py           # проверка, пишет state.json, шлёт в Telegram
python3 check_rzd.py --dry     # проверка без Telegram и без записи состояния
python3 check_rzd.py --reset   # забыть состояние
python3 check_rzd.py --test    # тестовое сообщение в Telegram
./deploy.sh public|private     # выложить на GitHub и запустить
```

## Ограничения

- GitHub запускает расписание не чаще раза в 5 минут и в загруженные часы опаздывает; место из возврата,
  которое разбирают за минуту, бот может не застать. Встроенный «Лист ожидания» РЖД покупает сам и быстрее.
- В приватном репозитории бесплатно 2000 минут Actions в месяц: каждые 5 минут — это ~8600 минут,
  поэтому приватный вариант работает раз в 30 минут. Публичный — без лимита, но логи запусков видны всем.
